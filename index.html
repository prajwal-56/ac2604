Accessible Coconut 26.04

A record of the work done so far porting Accessible Coconut — an accessibility-focused Ubuntu MATE derivative for visually impaired users — from its 22.04 release to a Kubuntu 26.04 base, "Resolute Raccoon."

Overview

Accessible Coconut (AC) 26.04 is a Linux distro built on top of Kubuntu with desktop environment as MATE. AC 26.04 continues that work on a newer base, using AC 22.04 as the reference for anything that already worked: keyboard shortcuts, panel layout, screen reader behavior, and the bundled application set.

The base for this release is a stock Kubuntu 26.04 ISO rather than Ubuntu MATE directly, because Kubuntu's installer (Calamares) and its accessibility stack behaved better as a starting point and in addition to it, the ubuntu 26.04's installer (subiquity) - lacks accessibility. The ISO is customized with Cubic, which chroots into the ISO's filesystem for editing and then regenerates the ISO from the modified chroot.

Converting the base from KDE to MATE followed a fixed sequence of checks so that nothing was removed before its dependencies were understood:

  • Confirm what the KDE/Plasma stack pulls in, and that Calamares does not depend on it.
  • Remove kubuntu-desktop, plasma-desktop, and sddm, then clear orphaned dependencies, and re-confirm Calamares survived the removal.
  • Install mate-desktop-environment-core and lightdm.
  • Resolve the display-manager conflict by setting MATE as the default session in LightDM's .conf.d configuration, since a live ISO auto-logs into a session rather than showing a login picker.
  • Verify only one display manager is enabled, a MATE session entry exists, and Orca is installed.
  • Confirm the Calamares installer launcher still exists on the live desktop.
  • Clean the chroot and generate the ISO.
  • Test in an emulator with Orca actually driving the desktop and the installer, then test on physical hardware (live boot).

Testing throughout has relied on invoking QEMU directly rather than Cubic's built-in test button, which has proven unreliable. The fixes described below were found through that testing process, including a round of tester feedback that flagged a specific set of missing shortcuts, panel behavior, and applications — most of which are now resolved.

Fixes & Customizations

Each of the following was broken or missing at some point during the build and has since been fixed and verified on a fresh boot, unless noted otherwise.

Calamares installer crash Fixed

The installer crashed during install for two separate reasons that had to be found and fixed independently.

First, Cubic's own GUI fields for Volume ID, Release, and Disk Name were malformed. Cubic regenerates the ISO's .disk/info file from these GUI fields every time the ISO is generated, which means any manual edits made directly to that file are silently overwritten on the next build. The fields now use corrected values entered through the Cubic interface itself, rather than edited in the file afterward.

Second, and the actual root cause of the crash: Ubuntu 26.04 renamed casper's CD-ROM setup script from 41apt_cdrom to 41apt_build_cache_cdrom. The new script only preserves an existing cdrom.sources file — it does not create one — and that file was missing entirely from the chroot. It was restored by extracting a working copy from a stock Kubuntu 26.04 squashfs and placing it at /etc/apt/sources.list.d/cdrom.sources inside the chroot.

Related fix

A separate installation failure, seen after an earlier round of testing, was traced to a file that had been lost during a prior cleanup pass rather than to a new bug. Once restored, a full install was completed and verified on a fresh boot.

Panel layout Fixed

The panel layout is defined as a system-wide dconf default rather than a per-user setting, so every account gets the same layout without any first-login configuration step. The reference layout was captured directly from a live boot of AC 22.04 using dconf dump, rather than reconstructed from memory.

The top panel carries the menu bar, a Firefox launcher, the notification area, and the combined system tray. The bottom panel carries the Brisk application menu, the trash applet, show-desktop, the workspace switcher, and the window list.

An earlier build shipped with MATE's default Compact Menu on the bottom panel instead of Brisk Menu, which testing flagged as inconsistent with Accessible Coconut's expected layout; this has since been corrected. The applet identifiers used in the panel configuration were confirmed by reading each applet's .mate-panel-applet file directly rather than guessed from its package name.

The system tray is handled by a single combined indicator applet rather than several separate ones, and getting it to actually display Wi-Fi, Bluetooth, volume, and the clock required installing the full Ayatana indicator service stack — not just the applet package — along with network-manager-gnome and blueman (for bluetooth).

Keyboard shortcuts Fixed

All shortcuts carried over from AC 22.04 have been reimplemented and confirmed working on a fresh live boot. On this MATE build, GNOME-style custom keybindings under the media keys settings daemon are not supported, so every shortcut is instead wired through the Marco window manager's own key-binding schema, which pairs a key combination with a command to run.

Volume shortcuts talk to pactl directly rather than going through a helper script. Panel-switching with Super+Tab needed an extra step: it required remapping Marco's own built-in panel-cycling shortcut, since that shortcut already existed and would otherwise conflict.

A separate lesson from this work: a dconf keyfile that defines multiple keys under the same schema path must use a single section header. Splitting them across duplicate headers in the same file causes the parser to silently fail, with no error to point at the cause.

IBus-Braille toggle Fixed

Bound to Super+I, using the same Marco key-binding mechanism as the other shortcuts. The script behind it checks whether the IBus daemon is already running and whether IBus-Braille is the currently active input engine, and switches to it if not, rather than blindly restarting the input method each time.

Orca at the login screen Fixed

Testing found that the screen reader was silent at the LightDM login screen, which is a separate problem from Orca not starting inside a user's own session. This was fixed in LightDM's greeter configuration, which now explicitly launches Orca and enables its accessibility state for the greeter itself.

Orca autostart Fixed

Once a user is logged in, Orca now starts automatically as a system-wide default rather than something each user session has to enable. This is set through the same system dconf mechanism as the panel layout, with a system profile pointing user sessions at that shared configuration.

Casper overlay crash Fixed

A known issue in Ubuntu 26.04's live boot process: the overlay filesystem module is now built directly into the kernel rather than loaded as a module, but casper's boot script still tries to load it and treats the failure as fatal. The fix removes that fatal failure path from the casper script and rebuilds the initramfs so the change takes effect at boot.

Rebranding Fixed

Visual and identity branding is complete: desktop wallpaper, the LightDM greeter background, the Plymouth boot theme, system identification files, and the GRUB boot menu entries and boot chime all reflect Accessible Coconut rather than the Kubuntu base.

The live session's default username and hostname required special handling. Editing /etc/hostname or the casper configuration inside the chroot does not stick, because casper overwrites both at boot time from settings baked into the initramfs itself. The fix was to unpack the initramfs, edit the relevant configuration there, and repack it, rather than editing the chroot's own copy of those files.

Known Issues

Open items that still need investigation before release. These are tracked here deliberately rather than folded into the fixes above.

Post-install GRUB menu branding Open

The live-boot GRUB menu correctly shows Accessible Coconut branding. What hasn't been confirmed yet is whether that branding survives a full install — Calamares runs its own update-grub inside the newly installed system, using that system's own GRUB configuration and distributor name, which is a separate code path from the ISO's own GRUB menu. This needs to be checked and confirmed after booting a fully installed system and inspecting its GRUB menu directly, rather than assumed from the live environment.

Orca voice sounded different during install Open

During a test install, Orca's voice did not match what was expected. It isn't yet clear whether this is a quirk specific to the Calamares installer environment or a genuine configuration bug. This needs to be re-checked from inside a fully installed system rather than the live/installer environment. The fix is simpler for this btw

Sharada Braille Writer unavailable Open

The PPA that provided this application no longer resolves for this release's codename, so it cannot currently be installed. This is documented as a known gap rather than a bug to fix, unless an alternative source is found.

Technical Learnings

Patterns worth remembering for the rest of this build, and for whoever picks it up next.

  • Cubic regenerates .disk/info from its own GUI fields on every ISO generation. Fix metadata like Volume ID and Release Name in the GUI itself, not by hand-editing the file afterward.
  • Ubuntu 26.04 renamed casper's CD-ROM script and changed its behavior: it now only preserves an existing cdrom.sources file rather than creating one, so a base image that lacks it will need that file seeded manually.
  • gsettings set only works inside a live session with a running D-Bus session bus. It silently does nothing when run inside a chroot, which can look like success at the time and only surface as a problem later. All permanent settings need to be written as dconf system keyfiles instead.
  • MATE schema paths are not always cased the way their schema ID suggests — always confirm the real path with dconf dump before writing a keyfile rather than assuming.
  • A live session can show a setting "working" after a manual gsettings set even across a reboot, because a user's own dconf database overrides the system database. Settings should always be verified from a completely fresh session, not a reused one.
  • Keybinding conflicts can happen at the window-manager level before the settings daemon ever sees the key press, which is why some shortcuts needed a conflicting built-in binding remapped rather than just adding the new one.
  • A single dconf keyfile section must not be split across duplicate headers — doing so fails silently rather than raising an error.
  • Cubic's initramfs is managed separately from the chroot's own filesystem. Anything casper sets at boot time — hostname, casper configuration, hosts file — will overwrite whatever was edited in the chroot, so those changes have to be made inside the initramfs itself.
  • Calamares runs its own GRUB update inside the freshly installed system, using that system's own configuration rather than anything set at the ISO level.
